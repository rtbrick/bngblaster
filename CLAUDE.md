# Project context for Claude Code – BNG Blaster

## About this project

BNG Blaster is an open-source network tester for routing and access protocols, developed by RtBrick.
It is written in C, runs on modern Linux systems (bare metal, VMs, containers) and is designed for high 
scaling with a low CPU/memory footprint.

Key capabilities:
- Access protocols: PPPoE, IPoE (DHCPv4/v6), L2TPv2, IPTV/IGMP, QoS, forwarding verification, convergence testing.
- Routing protocols: IS-IS (incl. Segment Routing), OSPFv2/v3, LDP, BGP (millions of prefixes).
- Traffic generation: millions of tracked flows, QoS verification, convergence measurements.

All protocols are implemented in user space from scratch and optimized for performance.

## Tech stack

- **Language**: C (core), some helper/tooling in Python/Shell.
- **Platform**: Linux 64-bit (Ubuntu and Debian recommended).
- **Build system**: `cmake`, with generated Makefiles.
- **Configuration**: JSON configuration files.

## Repository structure

## Directories and files to ignore

Do not spend time reading or modifying generated/build artifacts. These directories and patterns should be treated as ignored:

- `tmp/` – Temporary files.
- `docs/` – Documentation generated by Sphinx (should be ignored).
- `build/` – CMake build directory (generated binaries, objects, caches).
- `cmake-build-*/` – IDE/tool-generated CMake build folders.
- `bin/`, `lib/`, `obj/` – Build output directories, if present.
- `*.o`, `*.a`, `*.so` – Compiled objects and libraries.
- `CMakeCache.txt`, `CMakeFiles/` – CMake internal files.
- `*.log`, `*.pcap`, `*.cap` – Runtime logs and packet captures from test runs.

When planning changes, focus on source code under `code`. Avoid proposing edits in generated or binary directories.

## Coding style & conventions

- **C style**:
  - Clear, readable C code in the style of network software (no excessive macros unless necessary).
  - Use descriptive names for functions and variables (e.g., `session_create`, `bngblaster_ctx`).
  - Use `bbl_` as abrbreviation for BNG Blaster.
  - Optimize for performance and loss less traffic. 
- **No unnecessary globals**:
  - Encapsulate per-session/per-interface state in structured context objects.
- **Comments**:
  - Short, precise comments for complex logic (FSM transitions, timer handling, packet parsing).
  - No redundant comments that merely restate the code.
- **Portability**:
  - Code should run on modern 64bit Linux systems; avoid platform-specific assumptions unless necessary.
- **Scaling**:
  - 20 million traffic flows
  - 200 GBps symetric traffic with DPDK or AF_XDP

When modifying or adding code:
- Align with the existing style in the repo.
- Keep changes minimal and focused on the concrete task.
